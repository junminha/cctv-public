# 증거 보기·다운로드·미리보기 구현 계획

> 작성: 2026-10-26, `work/b-app`. **계획만 작성했으며 아래 신규 API·화면은 미구현이다.**

**요구 기준:** 이번 사용자 요청, `AGENTS.md`, `cctv 최종.md` §9, `shared/API.md` v0.2·v0.4, `shared/시연후-할일.md`. 아래의 “제안”은 사용자 확정 사항과 구분한다.

“브라우저 보기”는 기존 웹 UI에서 열 수 있는 동작이며, 파일 API의 inline 제공과 구별한다. “미리보기”는 목록 썸네일·내장 재생·라이트박스이다.

### 파일·보존·응답에서 확인한 사항

- 첨부는 서명으로 JPEG/PNG/WebP, WAV/MP3/M4A/WebM, MP4/MOV/WebM을 구별한다. ISO-BMFF와 WebM의 음성/영상 구별 일부는 선언 MIME도 사용한다. **서명 판정은 전체 디코딩·악성 파일 안전성·재생 호환 보증이 아니다.** 이미지 15MiB, 음성 25MiB, 영상 100MiB, 신고당 10개이며 개별 동의가 필요하다. 저장 시 크기·SHA256·수신 시각·원래 이름을 기록하지만 촬영 시각/EXIF 추출은 없다. [S2]
- 보존 클립은 승인된 cam-01/02/03만 가능하다. A 녹화의 remux 파생 MP4이며 원본과 바이트가 같다는 뜻이 아니다. 요청 구간·실측 길이·저장 시각·상위 export 시각·해시를 기록한다. 다운로드마다 전체 해시를 다시 읽으므로 Range 재생 시 반복 비용이 생길 수 있다. [S3]
- 근거 JPEG는 `vision._result`에서 복사한 이미지에 검출 상자·문구를 그린 **분석본**이다. `timestamp_seconds`는 구간 내 상대 시각이다. 저장 크기·SHA256·개별 생성 시각은 근거 항목에 없다. worker는 재분석 시작 시 신고별 분석 폴더를 삭제해 같은 파일명을 재사용한다. 분석 캐시는 보존 목록과 별개다. [S5,S9]
- ZIP은 report/clips/audit/manifest JSON과 선택적 첨부·보존 영상·analysis 폴더 파일을 넣는다. 분석 캐시 MP4도 포함될 수 있지만 개별 분석 MP4 보기 API는 없다. 파일별 bytes/SHA256, 첨부·보존 영상의 저장 해시 일치 여부를 기록하고, 누락 파일은 `missing`에 둔다. **불일치는 ZIP 생성을 막지 않고 false로 기록한다.** manifest 자신은 `files[]` 해시 목록에 포함되지 않는다. 응답 후 임시 ZIP을 지운다. [S1,S4]
- 저장 해시 일치는 촬영 내용의 진실성·촬영 시각·법적 증거능력 증명이 아니다. 이 구별은 화면·내보내기 설명에서도 유지한다. [S9 §9.1]

| 응답 | Content-Type | Content-Disposition | Cache-Control·감사 현재 |
|---|---|---|---|
| 첨부 GET | 판정한 MIME | `attachment`, 저장용 UUID 파일명 | 명시적 Cache-Control 없음. `attachment_downloaded` 요청 기록, 다운로드 시 해시 재검사 없음 [S1,S2,S11] |
| artifacts GET | `image/jpeg` | 명시하지 않음 | `private, max-age=60`. 해당 경로에 열람 감사 호출 없음 [S1] |
| clips download | `video/mp4` | `attachment`, clip UUID.mp4 | 명시적 Cache-Control 없음. 검증 통과 후 `clip_downloaded` [S1,S3,S11] |
| package.zip | `application/zip` | `attachment` | `no-store`. 생성 전에 `report_package_exported`, 생성 실패도 이 요청 기록은 남을 수 있음 [S1,S4] |

Range는 **기존 지원을 유지·보강**한다. 설치된 FileResponse는 Accept-Ranges/Content-Length/ETag/Last-Modified와 단일·다중 Range, 206, 잘못된 범위의 400/416, If-Range 처리를 갖고 있다. 기존 클립 테스트에도 `bytes=0-9` → 206 검사가 있다. 다만 이번에 그 테스트나 실제 재생을 실행한 것은 아니다. [S10,S11]

프록시는 HttpOnly·SameSite=strict 쿠키 값을 서버 측 Bearer로 바꾸고 요청/응답 body를 스트리밍한다. 요청 Content-Type·Range, 응답 Content-Type/Length/Range·Accept-Ranges·Disposition·Cache-Control을 전달한다. **If-Range, ETag, Last-Modified는 전달 목록에 없고 HEAD export도 없다.** `fetch(cache:'no-store')`는 upstream fetch 설정이며, 이것만으로 브라우저 캐시 금지가 보장되지는 않는다. [S8]

## 2. 선택안과 화면 계획 — 제안

검토안은 (A) 기존 다운로드 링크만 보강, (B) 기존 다운로드 + 공통 인증 뷰어, (C) 별도 미디어 관리 서비스이다. A는 빠르지만 재생·전체 근거 탐색·파일 정보 요구를 충족하지 못한다. C는 별도 권한·저장·배포 관리가 추가된다. **B를 추천한다.** 후속 작업의 기본안이며 사용자가 아직 이 구현 방식을 승인한 것은 아니다.

### 관리자 상세

기존 4개 탭은 유지한다. `ReportGuidance`는 대응·위치 안내 역할을 유지하고 파일 뷰어를 넣지 않는다.

### 크게 보기·재생·파일 정보

- 공통 모달은 이미지 `맞춤/100%/확대/축소`, 확대 상태 이동, `이전/다음`, 현재 번호·전체 개수, 닫기를 제공한다. 이미지 영역은 `object-fit: contain`으로 전체를 보인다. 자르거나 분석본을 원본처럼 표현하지 않는다.
- 모달은 이름 있는 dialog, 초점 가두기·복귀, Esc 닫기, 좌우 화살표 이전/다음, Home/End 처음/끝을 지원한다. 재생기·입력에 초점이 있으면 해당 키를 가로채지 않는다. `+/-/0` 확대/축소/맞춤 단축키와 버튼을 함께 제공한다.
- 영상은 기본 `<video controls preload="metadata" playsInline>`와 포스터, 음성은 `<audio controls preload="none">`를 쓴다. 자동 재생하지 않는다. 닫기·신고 변경·자료 변경 시 정지하고 src를 해제한다. 재생 실패 시 오류 안내와 원본 다운로드를 남긴다. MOV/M4A/WebM의 실제 코덱 호환은 후속 합성 파일 검사로 판정하며, 첫 단계에서 무조건 재인코딩하지 않는다.
- 파일 정보: 이름, 판정 MIME·크기, 카메라/첨부 ID, 구분, 수신/저장 시각(KST+원시 UTC), 촬영 시각, 상대 프레임 시각, 전체 SHA256·복사, 검증 상태를 표시한다. 촬영 시각을 모르면 **`촬영 시각 미확인`**이다. `window.start + timestamp_seconds`는 `영상 구간 기준 추정 시각`으로 표시하고 실제 촬영 메타데이터와 구별한다.
- 구분 문구: `신고자 업로드 원본`, `A 녹화 remux 보존 사본`, `AI 표시가 포함된 분석본`, `미리보기용 축소본`. 근거 이미지의 “원본 보기”는 `분석 이미지 크게 보기`로 고친다. SHA256은 `저장 시 해시/현재 파일 해시/일치/불일치/미확인`을 구별하고 축소본 해시를 원본 해시로 표시하지 않는다.
- 직각, 1px `--rule` 선, `--surface/--chart/--ink/--ink-soft`, 강조 `--tide`, 주의 `--amber`, 오류 `--signal`, 초점 `--beacon`을 사용한다. 둥근 모서리·그림자는 넣지 않는다. 1366×768·1920×1080에서 모달·버튼·긴 이름·64자리 해시가 넘치지 않게 한다. [현재 토큰: `app/globals.css`]

### `/live` 읽기 전용 범위 — 확인 전 기본 제안

`분석 자료·모델`의 자료 항목과 타임라인의 근거 이미지에서 같은 뷰어를 연다. 현재 선택된 신고의 자료만 조회한다. 명시적으로 누르면 사진·영상·음성을 볼 수 있게 하되, **신고자 원본을 전시장에 자동 확대·자동 재생하지 않는다.** 모달을 연 동안 자동 신고 전환을 잠시 멈추고 닫으면 이전 자동/고정 모드로 돌아간다.

보존 실행·대응 기록·종결·파일 삭제·ZIP/개별 반출 버튼은 `/live`에 추가하지 않는 안이다. 공통 뷰어에 `allowDownload=false`를 전달해 도구모음·오류 대안의 다운로드와 manifest 반출도 숨긴다. 다운로드는 관리자 상세로 이동해서 한다. 단, 브라우저 저장·개발자 도구·네이티브 재생기의 저장 동작을 완전히 차단할 수 있다는 뜻은 아니다. 자료 GET으로 생기는 열람 감사 기록은 읽기 전용 UI와 별개이며 담당자의 실행 기록으로 취급하지 않는다. 기존 긴급 알림 확인·보기 동작은 이 기능에서 바꾸지 않는다. 전시 노출 범위는 §7의 확인 질문이다.

## 3. 서버·프록시 변경 계획과 계약 초안

**판단:** 웹만 바꾸면 다운로드 링크·일부 JPEG 확대는 가능하지만, 요구한 inline 재생·캐시 금지·썸네일·자료별 정보/감사 구분을 충족하려면 B와 프록시 변경이 필요하다. **이번에는 API.md를 바꾸지 않는다.** 구현 승인 후 코드보다 먼저 아래 초안을 `shared/API.md` 새 확장 절에 기록한다. 번호는 당시 마지막 버전을 확인해 정한다.

### 제안 계약

| 메서드·경로 | 제안 동작 |
|---|---|
| GET `/api/v1/admin/reports/{id}/evidence` | 관리자 자료 목록. `items[]`, `analysis_started_at`, `warnings[]`. 첨부·현재 분석의 scan/focus/all/phone·보존 클립만 열거. 공공 CCTV 영상·임의 파일 경로는 받지 않음 |
| GET `/api/v1/admin/reports/{id}/evidence/{item_id}?verify=true` | 관리자 파일 정보. 명시적 `해시 검증` 동작에서만 현재 해시를 읽어 `current_sha256/integrity`를 반환. 불일치도 정보 응답에는 표시하며 미디어 보기는 409로 차단 |
| GET 기존 첨부 경로 `?disposition=inline` | 소유자·관리자, 원래 파일을 inline 제공. 생략 시 기존 attachment 다운로드 유지 |
| GET 기존 artifacts 경로 `?analysis_started_at=...&disposition=inline` | 관리자, 현재 결과의 항목인지 검증. disposition은 inline 또는 attachment. 기본 inline 유지, 명시적 개별 다운로드 추가. 재분석 시작/버전 변경 시 409 |
| GET `/api/v1/admin/clips/{clip_id}/view` | 관리자, 검증한 보존 MP4 inline. 기존 `/download` 유지 |
| GET `/api/v1/admin/reports/{id}/evidence/{item_id}/thumbnail` | 관리자, 크기 고정 JPEG. 원본 이미지·영상 포스터만, 음성은 썸네일 URL 없이 종류 아이콘. 분석 항목은 버전 필수 |
| GET `/api/v1/admin/reports/{id}/manifest.json?media=true&disposition=inline` | 관리자, ZIP과 동일 규칙의 파일 목록·SHA256·missing. media는 true 또는 false, disposition은 inline 또는 attachment. ZIP 파일을 만들지 않고 JSON만 반환. 기본 inline |

`EvidenceItem` 제안 필드:

```text
id, category(attachment|artifact|clip), kind(image|audio|video), label,
attachment_id?, clip_id?, camera_id?, artifact_kind?(scan|focus|all|phone),
analysis_started_at?, representation(upload_original|remux_copy|analysis_overlay),
content_type, bytes, stored_at?, captured_at?(null 허용), timestamp_seconds?,
recorded_sha256?, current_sha256?, integrity(unknown|match|mismatch),
available, view_url?, download_url?, thumbnail_url?
```

`id`는 서버가 생성·해석하는 자료 식별자다. 첨부/클립은 `(report_id, category, 원래 ID)`, artifact는 `(report_id, kind, owner, filename, analysis.started_at)` 튜플을 해시해 만들고 현재 서버 목록에서 해석하며 접근 권한을 대신하지 않는다. 클라이언트가 임의 절대경로·상대경로를 보내게 하지 않는다. 목록 조회마다 최대 2GiB 클립을 해시하지 않으며 초기에는 저장 해시·검증 미실행 상태를 준다. 실제 보기/다운로드·명시적 해시 검증·manifest 생성 때 현재 해시를 검증한다. artifact 크기·해시는 서버에서 현재 파일을 읽어 산출하고 버전별로 재사용한다. 실측되지 않은 시각·크기·해시는 null/미확인이다. 새 뷰어는 분석 버전을 반드시 전송한다. 기존 artifact URL의 버전 생략은 완료된 현재 분석만 반환하는 호환 모드로 남기되 버전 고정 조회라고 표현하지 않는다.

새 응답 필드 `analysis_started_at`의 값은 기존 `analysis.started_at`에서 가져온다. 분석 자료의 상세/썸네일 요청도 `?analysis_started_at=...`를 받으며 누락 시 422, 불일치 시 409다. queued/running 동안 자료 목록은 원래 첨부·보존 클립만 주고 artifacts를 생략하며 `analysis_started_at=null`, `warnings`에 “분석 중 · 근거 자료 준비 전”을 넣는다. 분석이 없으면 빈 근거 목록으로 처리한다. 기존 분석 결과가 DB에 남아 있다는 이유로 이를 새 분석의 근거로 제공하지 않는다.

### 응답·무결성·경로 규칙

- 파일 보기/다운로드·썸네일·목록·manifest·ZIP 및 관련 오류 응답을 **`Cache-Control: no-store, private`**로 통일한다. `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`를 적용하고 프록시가 전달한다. 기존 JPEG의 60초 캐시를 제거한다. 서버 내부 썸네일 캐시는 브라우저 캐시와 별개로 관리한다.
- disposition은 inline/attachment만 허용한다. 파일명은 경로·제어 문자·CRLF를 제거하고 RFC 호환 filename/filename*로 설정한다. 원래 이름은 화면 텍스트로 이스케이프하고 경로 결정에 사용하지 않는다.
- 기존 FileResponse의 Range를 사용하고 프록시에 If-Range·ETag·Last-Modified·HEAD 전달을 보완한다. B의 해당 파일 경로도 명시적으로 HEAD를 지원하고 파일 body·열람 감사는 만들지 않는다. `GET Range`의 206·400·416·Content-Range/Length를 끝까지 보존한다. ZIP은 응답 후 임시 파일 삭제 구조이므로 이어받기 보장을 약속하지 않는다.
- 첨부도 실제 보기/다운로드 전에 저장 bytes/SHA256과 비교하고 변조 시 409를 반환하는 안이다. 보존 클립의 기존 검증을 약화시키지 않는다. 대용량 클립의 반복 Range 해시는 초기에는 현행 검증을 유지해 정확성을 우선하고, 지연을 측정한 뒤 별도 승인 없이 검증을 생략하지 않는다.
- ID·kind·owner·파일명 허용 목록과 DB 소속을 검증한다. `resolve()` 후 루트 내부인지, symlink/junction을 따라 바깥으로 나가지 않는지 확인하고 정규 파일만 제공한다. URL 인코딩된 `..`, `/`, `\`, Windows 드라이브·UNC, 다른 신고의 ID, 현재 결과에 없는 artifact를 차단한다. 기존 artifacts 정규식만으로 모든 파일시스템 경계가 검증됐다고 주장하지 않는다. ZIP rglob 수집도 같은 경계를 적용한다. [현재 구현: S1,S2,S4]
- 재분석은 폴더를 교체하므로 URL query만 추가해서 버전 고정이 된다고 보지 않는다. **제안:** worker의 신고 폴더 교체와 근거 JPEG의 검증·읽기에 같은 신고별 잠금을 짧게 사용한다. 이미지/썸네일 입력은 잠금 안에서 버전 확인 후 bytes로 확보하고 잠금을 푼다. 분석 실행 전체를 잠그지 않는다. 새 분석 자료 요청은 queued/running 또는 버전 불일치면 409이고, 이미 확보한 이미지에는 그 버전을 표시한다. 원래 첨부·보존 클립은 재분석과 무관하게 계속 볼 수 있다.
- ZIP/manifest는 시작 시점의 report/분석 버전/자료 목록을 고정한다. media=true인 분석 자료 수집은 queued/running이면 409로 막는다. 생성 중 파일마다 그리고 응답 직전에 **queued/running 상태와 분석 버전을 함께** 다시 확인하고, 교체·삭제 경합이면 부분 ZIP을 지운 뒤 409를 반환한다. 새 분석을 저장하기 전에는 이전 started_at이 남으므로 시각 비교만으로 판정하지 않는다. 완성된 일관된 이전 버전 ZIP은 이후 재분석이 시작돼도 제공할 수 있다. 대용량 ZIP 생성 전체를 worker 잠금으로 막지 않는다. 분석 자료를 넣지 않는 media=false는 분석 중에도 허용한다. 경합 재현 테스트를 먼저 쓰고 worker 수정은 폴더 교체와 JPEG 읽기의 경계에만 한정한다.
- standalone manifest와 나중에 생성한 ZIP의 audit/generated_at은 다를 수 있다. manifest에 `generated_at`, `includes_media`, 분석 버전을 표시하고 **해당 ZIP 안 manifest를 그 ZIP의 최종 검증 목록**으로 안내한다. manifest는 SHA256 목록이지 디지털 서명이나 진본 인증서가 아니다.
- 현재 `exports.py`는 해시 계산과 ZIP 쓰기를 따로 읽는다. 그 사이 파일이 바뀌면 해시와 ZIP 내용이 어긋날 가능성이 있다(코드상 경합 가능성, 실제 발생 확인 아님). 후속 구현은 ZIP 멤버에 쓰는 동일 chunk에서 SHA256·bytes를 누적하고 그 값을 manifest에 기록한다. 저장 해시와 비교할 때도 이 값을 사용하며, 별도 선행 해시 결과를 ZIP 내용의 해시로 재사용하지 않는다.

### 썸네일·재생 호환

이미지는 방향 보정 후 긴 변 최대 320px JPEG로 만들고 원본을 덮어쓰지 않는다. 영상은 로컬 업로드/보존 파일의 첫 디코딩 가능한 프레임을 같은 크기로 만든다. 자료가 없는 경우 기존 AI 근거를 원본 영상 포스터인 것처럼 대체하지 않는다.

FFmpeg/ffprobe는 기존 `media.tool()`로 찾는 **B의 실행 도구**를 재사용한다(`setup_tools.py`, `tools/ffmpeg` 또는 명시 환경/시스템 경로). 바이너리·생성물은 Git에 넣지 않는다. URL 입력 금지, 로컬 파일만 허용, 외부 참조·네트워크 프로토콜 차단, 실행 10초·동시 1개·썸네일 최대 256KiB를 제안한다. 이미지 픽셀 수 40MP 초과·손상·영상 디코딩 실패는 미리보기 실패로 처리하고 정상 원본 다운로드 기능과 구별한다. 이 한계값은 제안이며 테스트 결과로 조정 시 문서에도 남긴다.

파생물은 설정된 B 데이터 루트 아래 `previews/`에 원본 해시+버전+변환 규격 키로 저장하고 부분 파일 후 rename한다. 캐시 유효기간 24시간·상한 256MiB·오래된 항목 우선 정리는 제안값이다. 원본 삭제/교체 시 해당 파생물도 지운다. 미지원 코덱은 먼저 다운로드 안내로 처리하며, H.264/AAC 등 변환 재생본은 필요성이 확인되면 별도 단계로 추가하고 원본과 별도 해시·표시를 갖게 한다.

### 감사 기록 구분

기존 `attachment_downloaded`, `clip_downloaded`, `report_package_exported`는 명시적 다운로드 경로에서 유지한다. inline GET은 `evidence_view_requested`, 썸네일은 `evidence_preview_requested`, artifact 개별 다운로드는 `artifact_downloaded`, manifest는 `manifest_view_requested`/`manifest_downloaded`로 구분하는 안이다. 검증·권한 확인 후 성공 응답을 준비하는 시점에 기록한다. 이 이름은 **전송 요청 기록이며 사람이 끝까지 봤거나 다운로드 완료했다는 증거가 아니다.**

기존 `store.audit(event, actor, report_id, clip_id)`의 마지막 값에 `attachment:{id}`, `artifact:{kind}:{owner}:{file}:{version}`, `clip:{id}`처럼 서버가 만든 참조를 넣는 최소 변경안을 우선한다. 기존 clip ID 의미가 필요한 소비자는 그대로 유지한다. GET Range마다 요청 기록이 남고 HEAD는 제외한다는 규칙을 문서화한다. 중복을 몰래 사람의 열람 건수로 집계하지 않으며, 요청 수가 과도하면 후속으로 논리적 열람 세션 집계를 검토한다. 원문·로컬 경로·토큰·파일 body는 감사 값에 넣지 않는다. ZIP의 audit.json에 새 유형도 포함한다.

## 4. 권한·개인정보·삭제

- 관리자 자료 목록·근거·보존 클립·manifest·ZIP은 관리자만 허용한다. 신고자는 기존처럼 자기 신고 첨부만 받을 수 있고, inline 추가도 같은 `owned_report` 검사를 거친다. 다른 신고자 첨부는 404, 관리자 전용 API에 신고자 토큰은 403, 미인증은 401을 유지한다. 신고자 상세 응답에 분석·CCTV·타인 파일을 추가하지 않는다. [S1,S9]
- 브라우저에는 동일 출처 `/api/b/...` URL만 주고 Bearer·A URL·로컬 경로를 노출하지 않는다. 프록시는 쿠키를 B에 그대로 전달하지 않고 서버 측 Authorization으로 변환하는 현재 방식을 유지한다. 파일 URL에 인증 토큰·서명키를 붙이지 않는다. 자료 ID가 든 URL도 민감할 수 있으므로 외부 referrer·외부 분석 도구로 보내지 않는다. [S8]
- 공개 CCTV는 좌표·목록 정보만 대상이다. 공공 영상 다운로드·미리보기·AI 처리나 기관 자동 전송을 새로 만들지 않는다. 보존은 승인 웹캠 3대의 현재 제한을 유지한다. [S3,S9]
- no-store는 향후 HTTP 캐시 저장을 제한하지만 이미 저장된 과거 브라우저 캐시·다운로드 폴더·OS 임시 파일·사용자 캡처를 원격으로 없애주지 않는다. 로그아웃/권한 상실 시 뷰어를 닫고 로컬 object URL을 해제한다. Service Worker·localStorage·IndexedDB에 미디어를 저장하지 않는다.
- `shared/시연후-할일.md`의 첨부·analysis·clips·DB 정리에 **previews, 내보낸 ZIP/manifest, 다운로드 폴더, 발표용 캡처·영상과 브라우저 정리**를 후속 구현 때 추가한다. 이번 계획 작성 중에는 삭제하지 않는다. 현재 자동 보관기간/탈퇴·삭제 API가 구현돼 있다고 가정하지 않으며, §9의 제안과 시연 후 필수 개선을 구별한다. 발표용 보존은 출연자 동의 범위를 다시 확인한다. [S9]

## 5. 단계별 작업·파일·완료 조건

다음 체크박스는 **향후 작업**이다. 각 단계는 실패 테스트 → 최소 구현 → 해당 검사 통과 → 범위 한정 커밋 순서로 한다. 병렬 worker/ZIP 경합은 재현 테스트 없이 수정하지 않는다.

|---|---|---|
| 0. 기반 확인·계약 | `shared/API.md`; 기존 `/live` 최종 커밋 재확인 | 현재 상태표 갱신, §3 계약·감사·호환 정책 확정. 승인 전 구현 금지 |

| 3. 웹 공통 뷰어·관리자 | `app/api/b/[...path]/route.ts`, `lib/api.ts`, 신규 `components/evidence-gallery.tsx`, `components/evidence-viewer.tsx`, `report-panel.tsx`, `app/globals.css`; 신규 `tests/evidence-ui.js` | `EvidenceItem` 타입·프록시 Range/HEAD·목록/모달/재생/다운로드·manifest. 파일 정보/재생 실패/키보드 검증 |
